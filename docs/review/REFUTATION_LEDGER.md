- **Falsy unsupported-option values ignored** (GLM5-era, re-refuted GLM9): setLogprobs(false) etc. are neutral no-ops, not errors.
- **System-role coercion unreachable via SDK enum** (GLM9-ref): the SDK MessageRole enum cannot express the flagged input; not triggerable.

- **Big-integer replay split rule** (glm12-8): raw-wire paths (zai arguments string, Anthropic accumulated input_json) accept beyond-int literals the platform decode keeps EXACT (`%.0f`-verified) and reject only true precision loss; decoded-only paths (Anthropic non-streaming input, pre-decoded zai members, the consolidated-payload oracle) keep the CONSERVATIVE walker rejection because post-decode exact and lossy big floats are the same double. Verifier-round addendum: the glm12-12 replay stamp does not survive a `toArray()`/`fromArray()` round trip (the vendor DTOs rebuild `new self`), so an exact-literal call that replays in-process rejects conservatively after array rehydration — the rehydrated call is a caller-built decoded-only value, judged by the conservative half of this same rule; not a parse/replay divergence within either surface. Do not flag the conservative rejection as a false positive, and do not flag the precise acceptance as missing validation.
- **Replay-stamp skip** (glm12-12): outbound replay guards skip the serializing oracle for `ReplayValidatedFunctionCall` instances — the args were validated at inbound acceptance and the SDK DTO is immutable (no setters), so the stamp can never outlive its arguments. Caller-built plain SDK instances keep the full oracle. Do not flag the skip as missed outbound validation.
- **Unrecognized 2xx probe bodies stay inconclusive** (glm12-1): only the models-list shape is VALID and only the `success:false`+definitive-code envelope is INVALID; any other 2xx body must neither report connected nor persist an unproven invalid verdict (core clears keys on false). Non-credential envelope codes (1113 balance) stay inconclusive like their 429 twin. Refined by glm13-2: the models-list shape is the ONE entry rule the parser also rejects through (`ZaiModelListParser::entry_failure_reason()`) — an empty `data` list and an incomplete page (`has_more`) are NOT the shape (inconclusive, superseding the verdict's earlier paginated-body tolerance); the chat filter and plan intersection stay catalog-only.
- **Empty wired credential authenticates nothing** (glm13-1): the SDK registry wires `ZAI_API_KEY=''` verbatim, so the probe treats an empty wired `ApiKeyRequestAuthentication` exactly like none (effective-key fallback), and `record_definitive_verdict()` records NOTHING for a request the empty credential flew — the verdict binding must name the credential that flew (an empty-wire 401 under the ladder/DB binding is the cross-credential poisoning class). Do not re-flag the empty-wire skip as missed validation.
- **Generation routes record definitive rejections** (glm13-6): a 401/403 on either surface's generation route records its invalid verdict through the availability base before the typed throw (request-time endpoint capture; glm13-1 binding discipline) — the same evidence the probe and both discovery routes persist. Status-judging parity with GLM10 #8's one-source decision; do not flag the recording as double-state.
- **Unknown delta on a never-started index is corruption** (glm13-4, supersedes the Codex R14 #3 seed tolerance): the synthesized-seed path is GONE — every delta type on an unstarted index rejects (input_json_delta through the tool-input channel, everything else through the malformed-event channel); unknown deltas on a STARTED block keep their forward-compatible tolerance. Position rejections (duplicate/contiguity, glm13-5) run before content validation in `start_block()`, so a position-rejected frame never latches the tool-input flag.
- **The tool-result response encodability guard stays PRE-mapping** (glm13-11 exception): the SDK parent's message mapping json_encodes the tool-result response and STRING-CASTS the failure, so by the createRequest() chokepoint an unencodable result has already laundered into `"content": "false"` — the whole-payload encodability net can never see it. Its guard stays eager in the typed walk while every other pure-encodability member rides the net with attribution-on-failure. Do not "complete" the restructure by moving it.
- **Both surfaces resolve the transporter before the guards** (glm13-12): the vendor's FINAL `generateTextResult()` calls `getHttpTransporter()` before `prepareGenerateTextParams()` on the zai surface — guards-first is structurally impossible there, so the zai_anthropic surface's own `generateTextResult()` mirrors the vendor-mandated order and identical misuse yields identical errors. Do not re-flag the order divergence in the other direction.
